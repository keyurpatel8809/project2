## 2 · Concept of the day (15 min)

### The journey of a Java program

```
  Hello.java  ──javac──▶  Hello.class  ──java──▶  JVM
  (source)              (bytecode,             │
                         portable)             ├─ Class loader: finds & loads .class files
                                               ├─ Bytecode verifier: is this safe?
                                               ├─ Interpreter: runs bytecode line by line
                                               └─ JIT compiler: hot code → native machine code
```

**Analogy:** bytecode is a recipe written in a universal cooking language. The JVM is the chef in each
kitchen (Windows, Linux, Mac) who reads that one recipe. The JIT compiler is the chef memorising the dishes
you order every day so they come out faster. That is "write once, run anywhere" and also why Java gets
*faster* the longer it runs.

| Term | What it is | One-liner for interviews |
|---|---|---|
| **JDK** | Java Development Kit: compiler (`javac`) + tools + a JRE | "What I install to build Java" |
| **JRE** | Java Runtime Environment: JVM + core libraries | "What is needed to run Java" |
| **JVM** | The virtual machine that executes bytecode | "The engine; it does class loading, verification, execution, memory management" |
| **JIT** | Just-In-Time compiler inside the JVM | "Turns hot bytecode into native code at runtime" |

### Where things live: stack vs heap

```
   THREAD STACK (one per thread)                HEAP (shared by all threads)
   ┌────────────────────────────┐              ┌──────────────────────────────┐
   │ main()                     │              │                              │
   │   int count = 3;      ─────┼── value 3    │   Account@7a1  { balance=500 }│
   │   Account a = ...;    ─────┼── reference ─┼─▶                             │
   │   String s = "hi";    ─────┼── reference ─┼─▶  "hi"  (String pool)        │
   └────────────────────────────┘              │                              │
                                               │   garbage collector works here│
                                               └──────────────────────────────┘
```

- **Stack:** method frames, local primitives, and *references*. Fast, thread-private, freed automatically when the method returns. Overflow → `StackOverflowError`.
- **Heap:** every object created with `new` (and strings). Shared, managed by the **garbage collector**. Exhaust it → `OutOfMemoryError`.
- Java is **pass-by-value**: for objects, the *value being copied is the reference*. That is why a method can change an object's fields but cannot make your variable point to a different object.

### `==` vs `.equals()`

```java
String a = "bank";
String b = "bank";             // same literal → same pooled object
String c = new String("bank"); // forces a new heap object

System.out.println(a == b);        // true  (same reference, string pool)
System.out.println(a == c);        // false (different objects)
System.out.println(a.equals(c));   // true  (same characters)
```

`==` asks "same object in memory?". `.equals()` asks "logically equal?" and does whatever the class defines
(for `Object` it defaults to `==`, which is why you override it).

## 3 · Hands-on task (10 min)

Create `Day01.java` and make every comment true by running it:

```java
public class Day01 {
    static void rename(Account acc) {
        acc.owner = "Changed inside method";   // mutates the shared heap object
        acc = new Account("Brand new");        // only rebinds the LOCAL reference
    }

    public static void main(String[] args) {
        Account a = new Account("Keyur");
        rename(a);
        System.out.println(a.owner);   // prints: Changed inside method   (why not "Brand new"?)

        String x = "java";
        String y = "ja" + "va";        // compile-time constant → pooled
        String z = new StringBuilder("ja").append("va").toString();
        System.out.println(x == y);         // true   (explain)
        System.out.println(x == z);         // false  (explain)
        System.out.println(x == z.intern());// true   (what does intern() do?)
    }
}

class Account {
    String owner;
    Account(String owner) { this.owner = owner; }
}
```

**Stretch (if time remains):** write a recursive method with no base case, run it, and read the
`StackOverflowError` trace. You just watched the stack fill up.

## 4 · Interview drill (5 min)

Answer out loud in under 60 seconds each, then open the model answer.

<details>
<summary><strong>Q1. Is Java pass-by-value or pass-by-reference? Prove it.</strong></summary>

Pass-by-value. For primitives the value is copied. For objects the *reference* is copied, so the method
can mutate the object's state but reassigning the parameter has no effect on the caller. The `rename()`
method above is the proof: the owner changed, but `a` still points to the original object.
</details>

<details>
<summary><strong>Q2. What is the difference between JDK, JRE and JVM?</strong></summary>

JVM executes bytecode and manages memory. JRE = JVM + standard libraries, enough to run programs.
JDK = JRE + development tools like `javac`, `jar`, `javadoc`. Since Java 11 Oracle ships only the JDK.
</details>

<details>
<summary><strong>Q3. Why is Java called "write once, run anywhere", and what is the catch?</strong></summary>

`javac` compiles to platform-neutral bytecode; any platform with a JVM runs it. The catch: you still need a
JVM for that platform, and native dependencies or OS-specific behaviour (file paths, line endings) can
break portability.
</details>
